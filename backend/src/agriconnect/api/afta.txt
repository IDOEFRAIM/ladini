C'est une excellente approche. **Priorité absolue à la stabilité du code** avant de construire le système de monitoring complexe.

Pour atteindre ton objectif, voici le plan de route par étapes logiques. On se concentre sur une structure qui ne te bloquera pas demain quand tu décideras d'ajouter la couche de monitoring.

---

### Phase 1 : Consolidation du Cœur (Objectif : 100% Fonctionnel)

Avant de monitorer, il faut que l'application soit "propre" au niveau de ses données.

1. **Fiabiliser le `WorkspaceStore` :**
* Assure-toi que chaque message reçu est systématiquement lié à un Workspace.
* *Action :* Implémente le pattern "Lazy Initialization" : si l'utilisateur n'a pas de workspace, le système en crée un par défaut (en mode "découverte") dès le premier message.


2. **Standardiser la réponse API :**
* Tes endpoints (Twilio, Market) doivent retourner des réponses uniformes.
* *Action :* Crée une classe `ResponseWrapper` pour que chaque retour soit toujours sous la forme `{"status": "...", "data": ..., "error": ...}`.


3. **Nettoyage du Worker Celery :**
* Vérifie que les `try/except` sont robustes dans `tasks.py`. Chaque erreur doit être loguée avec le `message_sid` et le `phone_number` pour que tu puisses plus tard faire le lien avec S3.



### Phase 2 : "Instrumentation" Légère (La préparation au monitoring)

C'est ici que tu prépares le terrain sans installer d'outils lourds.

1. **Logs en format JSON :**
* Configure ton `logging` pour sortir du JSON au lieu du texte. Ça ne change rien à ton code, mais tes logs deviennent exploitables instantanément par n'importe quel outil futur.


2. **Loguer le "Context" métier :**
* Dans ton `Orchestrator`, ajoute des logs aux étapes clés.
* *Exemple :* `logger.info("Agent analysis complete", extra={"phone": phone, "agent": "producer", "latency_ms": 150})`.
* Ces logs seront ton "or" plus tard pour le monitoring.



### Phase 3 : Mise en place de la pile de monitoring

Une fois que tout tourne en prod depuis quelques jours sans plantage :

1. **Loki + Grafana (Le Dashboarding) :**
* Installe Loki et Grafana via Docker Compose.
* Connecte tes logs JSON locaux à Loki.
* *Objectif :* Avoir un graphique qui montre le nombre de messages reçus vs messages traités.


2. **Export vers S3 (L'archivage) :**
* Utilise un simple script de rotation (Logrotate) pour archiver tes fichiers JSON.
* Programme un job Celery (Celery Beat) ou une Cron job qui synchronise ces fichiers vers S3 une fois par jour.

> * **Semaine 3 :** Tu branches Grafana pour visualiser les courbes.
